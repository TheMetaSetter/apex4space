Web developer handoff

Time-series API

This page explains the requests and replies in the generated OpenAPI file. It uses simple names and invented example values.

Cách trang web và API hoạt động cùng nhau

Trang web (web app) nhận thao tác của người dùng, gửi yêu cầu (request) đến API, rồi dùng dữ liệu trả về (response) để cập nhật bản đồ và biểu đồ. OpenAPI mô tả các đường dẫn (routes), trường dữ liệu và kiểu dữ liệu mà web app cần gửi hoặc nhận.

  1. Khi mở trang, gọi GET /v1/releases để lấy các bộ dữ liệu có thể dùng (releases). Dùng thông tin này để điền lựa chọn ngày, vùng, chỉ số và nền tảng.
  2. Khi người dùng chọn vùng và ngày, lưu lựa chọn đó làm trạng thái truy vấn (query state). MVP chỉ nhận hình chữ nhật qua bbox, theo thứ tự kinh độ tây, vĩ độ nam, kinh độ đông, vĩ độ bắc.
  3. Gọi POST /v1/analysis để lấy số liệu tóm tắt cho biểu đồ. Gọi POST /v1/hotspots/query để lấy các điểm cho bản đồ OpenLayers.
  4. Chỉ thay dữ liệu trên màn hình sau khi phản hồi thuộc truy vấn hiện tại đã về. Nếu người dùng đổi vùng hoặc ngày, hủy yêu cầu cũ (cancel stale request) và xóa điểm cũ để tránh hiện dữ liệu sai vùng.
  5. Nếu có trang tiếp theo, gửi next_cursor cùng đúng các trường truy vấn cũ. Không tự sửa cursor.
  6. Khi người dùng tải xuống, gọi POST /v1/exports với cùng lựa chọn. Dùng tên tệp từ Content-Disposition.

API sở hữu việc kiểm tra đầu vào (input validation), lọc dữ liệu, phân trang (pagination) và tạo tệp. Trang web sở hữu cách người dùng chọn dữ liệu và cách hiển thị kết quả. Trình duyệt không được chứa khóa FIRMS hoặc khóa ký cursor.

Gợi ý cho phần web

  • Dùng một đối tượng truy vấn chung (shared query object) cho biểu đồ, bản đồ và tải xuống để các phần dùng cùng vùng, ngày, release và nền tảng.
  • Trong OpenLayers, đổi thứ tự từ [west, south, east, north] sang thứ tự extent mà bản đồ đang dùng nếu cần. Khi đọc GeoJSON, tọa độ điểm là [longitude, latitude].
  • Phân biệt số 0 với null. Số 0 là kết quả đã biết; null nghĩa là chưa có giá trị dùng được. Hiển thị trạng thái đi kèm như missing hoặc not_validated.
  • Kiểm tra HTTP status trước khi đọc kết quả thành công. Khi có lỗi, hiển thị thông báo ngắn và giữ request_id để hỗ trợ tìm lỗi.

Thuật ngữ

  • API (Application Programming Interface): cách web app yêu cầu dữ liệu từ máy chủ.
  • OpenAPI specification: tài liệu máy đọc được về request và response của API.
  • Request / response: yêu cầu gửi đi / dữ liệu máy chủ trả về.
  • Release: phiên bản dữ liệu đã được chuẩn bị để API đọc.
  • GeoJSON: định dạng dữ liệu địa lý; ở đây mỗi hotspot là một điểm.
  • Cursor pagination: cách lấy danh sách dài thành nhiều trang bằng một cursor do máy chủ cấp.
  • CORS (Cross-Origin Resource Sharing): quy tắc cho phép trang web từ một địa chỉ gọi API ở địa chỉ khác; đây không phải đăng nhập.

Mỗi nhóm người dùng nhận được dữ liệu gì?

Cả ba nhóm dùng cùng một nguồn dữ liệu API. Website trình bày dữ liệu theo câu hỏi của họ. Kết quả phụ thuộc vào release, vùng, ngày, nền tảng và chỉ số mà họ chọn. Một truy vấn thường trả về hai phần: số liệu theo thời gian từ /v1/analysis và vị trí từng điểm từ /v1/hotspots/query.

Người ứng cứu khẩn cấp (emergency responders)

  • Trên bản đồ (map): mỗi điểm có thời gian observed_at, nền tảng platform, loại điểm hotspot_type, độ tin cậy confidence nếu có, và FRP frp_mw nếu có. Tọa độ GeoJSON dùng kinh độ trước vĩ độ.
  • Trên biểu đồ (time series): giá trị value theo ngày hoặc tháng, đơn vị unit, trạng thái status và cảnh báo warnings. Có thể dùng để nhận biết nơi hoặc thời điểm có nhiều tín hiệu.
  • Tải xuống (download): CSV chứa các quan sát trong lựa chọn hiện tại. Dùng để chia sẻ hoặc mở trong công cụ khác.

Dữ liệu này giúp họ xem tín hiệu cần chú ý. Đây là phát hiện hotspot từ vệ tinh (satellite hotspot detection), không phải xác nhận hiện trường (field confirmation) hay ranh giới đám cháy (fire perimeter).

Nhà khoa học (scientists)

  • Kết quả phân tích (analysis result): chuỗi calendar có giá trị, ngày bắt đầu/kết thúc, trạng thái, độ bao phủ dữ liệu coverage, cảnh báo và thông tin thiếu/không kiểm định. Phản hồi cũng nêu chỉ số unit, phương pháp method_id nếu có, và vùng được dùng used_area nếu có.
  • Dữ liệu điểm (point records): GeoJSON có tọa độ và thuộc tính như observed_at, platform, product, version, quality, bands, cùng mã tệp và dòng nguồn. Kết quả được chia trang bằng cursor.
  • Tệp xuất (export): CSV cho quan sát nguồn; JSON cho kết quả phân tích. Có thể dùng các trường nguồn để kiểm tra lại dữ liệu và cách xử lý.

Họ có thể lưu lựa chọn truy vấn (query parameters) để chạy lại cùng vùng, ngày, nền tảng, chỉ số và cách gộp. Cần giữ trạng thái như missing và not_validated khi diễn giải kết quả.

Quản lý đất đai (land managers)

  • Bản đồ khu vực (area map): vị trí hotspot trong hình chữ nhật được chọn, có thể lọc theo ngày và nền tảng.
  • Tóm tắt thời gian (time summary): số liệu theo ngày hoặc tháng, trạng thái dữ liệu và cảnh báo để theo dõi thay đổi trong khu vực.
  • Bản ghi (record): CSV của các điểm quan sát theo vùng và ngày đã chọn, để lưu hồ sơ hoặc chuyển cho nhóm.

Website chỉ nhận hình chữ nhật (bounding box) trong MVP. Nếu khu vực quản lý có ranh giới đa giác (polygon boundary), người dùng chọn hình chữ nhật bao quanh khu vực. Kết quả khi đó có thể gồm điểm nằm ngoài ranh giới thật.

Giới hạn chung: website trả dữ liệu trong release đã chọn và vùng/ngày được yêu cầu. Dữ liệu rỗng, thiếu, hoặc chưa được kiểm định phải hiển thị đúng trạng thái; không tự đổi thành số 0 hay kết luận về nguy cơ.
Start here: open the OpenAPI file to see every field and data type. This guide explains how to use it. The file comes from a test release. It does not show live data. The live API needs a selected release before it can start.

What is OpenAPI?

OpenAPI is a machine-readable list of API routes, request fields, and reply fields. A web app can use it to check request shapes or make types.

The file lists eight routes. It does not mean that real source data is ready.

Routes

GET /health/live

Checks that the app runs.

GET /health/ready

Checks that the selected release is ready.

GET /v1/releases

Lists releases and their supported dates, areas, metrics, and platforms.

GET /v1/releases/{release_id}

Reads public details for one release.

GET /v1/metrics

Lists metric names, units, and allowed time groups.

POST /v1/analysis

Gets a summary and day or month values.

POST /v1/hotspots/query

Gets source points as GeoJSON pages.

POST /v1/exports

Downloads analysis JSON or observation CSV.

Fields used by map requests

  • release_id: the release to read. Get valid IDs from /v1/releases.
  • bbox: a rectangle in EPSG:4326 order: west, south, east, north. Values are longitude, then latitude.
  • start_date and end_date: dates in YYYY-MM-DD form. The start is included; the end is excluded.
  • platforms: source platforms to include. Read allowed names from the release.
Rectangle input only: the current request has bbox. It does not accept a drawn polygon. For this MVP, send the rectangle bounds.

Get a time summary

Send a JSON body to POST /v1/analysis. Choose one metric and group the results by day or month.

{
  "release_id": "local-release",
  "bbox": [106, 10, 107, 11],
  "start_date": "2024-03-01",
  "end_date": "2024-03-03",
  "metric": "observed_hotspot_count",
  "aggregation": "day",
  "platforms": ["Aqua"]
}

The reply has one summary, a calendar list, and warnings. A period has a status and a value. A null value means no supported value is available. Do not show it as zero.

  • observed_zero means the selected source has zero points.
  • missing means data needed for the value is missing.
  • not_validated means the release has no checked method for that estimate.

Load map points

Send the shared fields and a platform list to POST /v1/hotspots/query. The first request can omit cursor.

{
  "release_id": "local-release",
  "bbox": [106, 10, 107, 11],
  "start_date": "2024-03-01",
  "end_date": "2024-03-03",
  "platforms": ["Aqua"],
  "page_size": 500
}

The reply is a GeoJSON FeatureCollection. Each point uses [longitude, latitude] coordinates. If has_more is true, send next_cursor with the same query to get the next page.

The cursor is signed by the server. Keep it as-is. Do not change the area, dates, platforms, release, or page size while using it.

Download results

Send the same area, date, release, and platform fields to POST /v1/exports.

{
  "release_id": "local-release",
  "bbox": [106, 10, 107, 11],
  "start_date": "2024-03-01",
  "end_date": "2024-03-03",
  "kind": "observations",
  "format": "csv",
  "platforms": ["Aqua"]
}
  • Use kind: "observations" and format: "csv" for source rows.
  • Use kind: "analysis" and format: "json" with metric and aggregation for a summary.

The response uses Content-Disposition for its file name. The OpenAPI response lists text/csv and application/json.

Handle errors

Use the HTTP status and the stable code field. Show a short message. Keep request_id so a user can report the problem.

{
  "code": "INVALID_REQUEST",
  "message": "The request fields are invalid.",
  "details": {"fields": []},
  "request_id": "server-created-id"
}

Schema note: the live app sends this error shape, but this OpenAPI file does not yet define an ErrorResponse schema. Ask the API owner if the error fields need a formal OpenAPI entry.

Keep the browser safe

  • Do not put FIRMS_MAP_KEY or CURSOR_SECRET in web code.
  • CORS lists allowed browser origins. It does not sign users in or protect the API from other clients.
  • Stop old map requests when the user changes the area or dates. Clear old points before showing new results.

Example release IDs and data values are invented. Check a release before making a live request.
